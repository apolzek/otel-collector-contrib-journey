# Estrutura do `exporter/kafkaexporter`

O `kafkaexporter` é o exporter que manda traces, logs, metrics e profiles para o Kafka
(usando a lib `franz-go`/`kgo`).

## Código principal

| Arquivo | Para que serve |
|---|---|
| `doc.go` | Doc do pacote + a diretiva `//go:generate make mdatagen` que dispara a geração de código do `metadata.yaml`. |
| `factory.go` | Ponto de entrada do componente: `NewFactory()`, os defaults (tópicos `otlp_spans`/`otlp_logs`/..., encoding `otlp_proto`) e a criação dos exporters de cada sinal. |
| `config.go` | Struct `Config` — tudo que o usuário escreve no YAML do Collector (brokers, auth, tópico, encoding, particionamento) + o `Validate()`. |
| `kafka_exporter.go` | O coração. Implementa a interface `messenger[T]`: pega o pdata, decide o tópico, deriva a chave da mensagem, particiona, serializa e publica no Kafka. |
| `marshaler.go` | Escolhe o marshaler conforme o `encoding` configurado (`otlp_proto`, `otlp_json`, `jaeger_*`, `zipkin_*`, `raw`...), inclusive resolvendo encoding vindo de extensions. |
| `partitioner.go` | Traduz a config de particionamento para uma `kgo.Opt` — sticky key (com hasher murmur2 ou compatível com Sarama), round-robin, least-backup ou uma extension customizada. |
| `request.go` | Caminho "Request-based" do `exporterhelper`: serializa o pdata em `kgo.Record` já na entrada da fila, para a fila guardar bytes prontos com tamanho conhecido (importante para persistent queue). |

## Configuração, docs e metadados

| Arquivo | Para que serve |
|---|---|
| `metadata.yaml` | Fonte da verdade do componente: nome, estabilidade por sinal, code owners e as métricas internas do exporter. Alimenta o `mdatagen`. |
| `config.schema.yaml` | Schema declarativo da config, usado para gerar/validar a documentação e os tipos de configuração. |
| `documentation.md` | **Gerado** a partir do `metadata.yaml` — lista as métricas de telemetria interna do exporter. Não edite à mão. |
| `README.md` | Doc para o usuário final: como configurar, opções, exemplos. |
| `Makefile` | Só um `include ../../Makefile.Common` — herda os alvos padrão do repo (`make lint`, `make test`, `make generate`...). |
| `go.mod` / `go.sum` | Este exporter é um **módulo Go independente** (o contrib tem um go.mod por componente). |

## Testes

| Arquivo | Para que serve |
|---|---|
| `*_test.go` (config, factory, marshaler, partitioner, request, kafka_exporter) | Testes unitários de cada peça. |
| `generated_component_test.go`, `generated_package_test.go` | **Gerados** pelo mdatagen: checam o ciclo de vida do componente e o `goleak` (vazamento de goroutine). Não edite. |
| `*_bench_test.go` | Benchmarks — de partes isoladas (partitioner, request) e um e2e do exporter inteiro. |
| `testdata/` | YAMLs de config usados pelo `config_test.go`, incluindo casos que devem falhar na validação. |

## `internal/`

| Pacote | Para que serve |
|---|---|
| `kafkaclient/` | Wrapper do client franz-go: envio das mensagens, métricas do produtor e construção dos headers Kafka. |
| `kafkarequest/` | Tipo `Request` da fila do exporterhelper — os `kgo.Record` já serializados, com sizer/merge. |
| `marshaler/` | Implementações concretas dos marshalers: `pdata`, `jaeger`, `raw`. |
| `metadata/` | **Gerado** pelo mdatagen: status do componente, feature gates e a telemetria interna. |
| `metadatatest/` | **Gerado**: helpers para asserir a telemetria nos testes. |

## Regra prática

Qualquer arquivo com `generated_` no nome, mais `documentation.md`, sai de `make generate`
a partir do `metadata.yaml` — se precisar mudar, mexa no YAML e regenere.
